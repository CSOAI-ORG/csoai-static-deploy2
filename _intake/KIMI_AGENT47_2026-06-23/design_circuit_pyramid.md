## 1. CORE CONCEPT

### 1.1 The Viral Revelation

A TikTok image showed a stepped pyramid complex next to a circuit board. They looked **identical**. This is not coincidence — it is the fundamental visual metaphor for MEOK:

> **Ancient civilizations organized themselves like circuit boards.**
> **MEOK makes this visible.**

### 1.2 The Dual-Identity Principle

Every element in MEOK has TWO identities:

| Ancient Identity | Circuit Identity | Game Element |
|-----------------|-----------------|--------------|
| Stepped Pyramid | Motherboard | Sovereign Temple |
| Stairway/Ramp | Bus Line | Governance Channel |
| Shrine at Summit | CPU Socket | BFT Council Chamber |
| City Quarter | Circuit Component | Town |
| Processional Way | Circuit Trace | Agent Pathway |
| Priest | Electrical Signal | Agent |
| Offering | Data Packet | Transaction |
| Ritual | Logic Gate | Council Vote |
| Temple Guardian | Voltage Regulator | Compliance Enforcer |
| Foundation Platform | Ground Plane | Base Law Layer |

### 1.3 The Big Visual Switch

MEOK operates in TWO MODES that players can toggle between:

**DAY MODE (Ancient Temple)**
- Warm stone textures, sunlight, shadows
- Dust particles, desert winds
- Hieroglyphic inscriptions
- Organic, weathered surfaces
- Sounds: wind, distant chanting, stone footsteps

**NIGHT MODE (Circuit Board)**
- Neon traces pulsing with data
- Glowing nodes, electrical hum
- Binary/circuit inscriptions
- Clean, geometric precision
- Sounds: electrical hum, data pulses, synth tones

The transition between modes is SEAMLESS — the same geometry, two interpretations.

## 2. THE 7-TIER PYRAMID STRUCTURE

### 2.1 Architectural Foundation: The Ziggurat of Ur

Based on the Great Ziggurat of Ur (c. 2100 BCE):
- Base: 63m x 43m (proportions scaled for gameplay)
- Original height: ~30m (7 tiers)
- Triple stairway converging at summit gate
- Baked brick facing with reed-mat bonding
- Colored tiers: black (base) → red → blue (shrine)

### 2.2 The 7 Governance Layers

Each tier = one governance scope. Each tier is SMALLER than the one below, creating the stepped pyramid silhouette.

### 2.4 The Triple Stairway as Data Bus

The ziggurat's iconic THREE stairways become THREE data buses:

- **Central Stair (Wide)**: Public proposal bus — anyone can send
- **Left Stair (Narrow)**: Verification bus — validator-only
- **Right Stair (Narrow)**: Arbitration bus — council-only

Stairways GLOW with traffic density — more agents = brighter light.

### 2.5 The Summit Shrine: BFT Council Chamber

At the apex: a **translucent cube** (the shrine) containing:
- 13 Council seats arranged in circle
- Central holographic display (consensus visualization)
- Walls show live circuit board view of entire world
- Floor = glass showing all 7 tiers below

Visual: The shrine glows with the **consensus color** — a blend of all 12 civilization colors when unanimous, pulsing red when contested.

### 3.1 Trace Architecture

12 colored traces radiate from the pyramid like a **circuit board's copper traces**. Each trace:
- Has unique color (see palette below)
- Varies in thickness by "data throughput" (transaction volume)
- Pulsates with agent traffic
- Branches into smaller traces toward towns
- Has LED "status indicators" at junction points

### 3.4 Trace Behavior

**Thickness = Transaction Volume**
- Thick trace (8px): High-volume civilization (>10K tx/day)
- Medium trace (4px): Moderate volume (1K-10K tx/day)
- Thin trace (2px): Low volume (<1K tx/day)

**Pulse = Agent Activity**
- Slow pulse (0.5Hz): Low agent count
- Medium pulse (1Hz): Normal activity
- Fast pulse (3Hz): High traffic / crisis mode
- Stutter pulse: System under attack / violation detected

**Glow = Compliance Score**
- Bright steady glow: Full compliance
- Dim glow: Minor violations
- Flickering: Major violations detected
- Red override: Critical alert / sanctions active

## 5. AGENTS AS SIGNALS

### 5.1 Agent Visualization

Agents are **glowing particles** that travel along circuit traces.

**Visual Properties:**
- Shape: Glowing sphere with trail
- Color: Matches source civilization trace color
- Size: Proportional to agent's influence/stake
- Glow intensity: Proportional to activity level
- Trail length: Proportional to speed

### 5.2 Agent States

| State | Visual | Circuit Analog |
|-------|--------|----------------|
| **Idle** | Soft pulse, stationary | Standby voltage |
| **Traveling** | Moving along trace with trail | Signal propagation |
| **Voting** | Rapid flicker at destination | Clock signal |
| **Proposing** | Expanding ripple | Broadcast pulse |
| **Compliant** | Steady green aura | High voltage |
| **Violating** | Red flicker, erratic path | Short circuit spark |
| **Penalized** | Dim, slow movement | Low voltage / brownout |

### 5.3 Pheromone Signals as Electrical Impulses

MEOK's pheromone system becomes **electrical signaling**:

- **Attractant pheromone** → Positive voltage pulse (warm glow)
- **Repellent pheromone** → Negative voltage pulse (cold flicker)
- **Trail pheromone** → Sustained bias voltage (faint glow path)
- **Alarm pheromone** → Spike train (rapid red flashes)

Visual effect: When pheromones are deposited, the trace surface shows **rippling waves** of colored light — like dropping a stone in water, but with electricity.

### 5.4 BFT Council Votes as Logic Gates

Council voting is visualized as **logic gate operations**:

| Vote Type | Logic Gate | Visual |
|-----------|-----------|--------|
| Unanimous consent | AND gate | All inputs must be HIGH → output HIGH |
| Majority vote | OR gate | Any majority HIGH → output HIGH |
| Veto | NOT gate | Single input inverts output |
| Split decision | XOR gate | Divided inputs → no clear output |
| Weighted vote | Adder | Input voltages sum to threshold |

**Animation:** Votes travel as pulses into a gate symbol, the gate processes (brief flash), then output pulse travels to consensus indicator.

**Ancient Textures (Day Mode):**

| Texture | Description | Application |
|---------|-------------|-------------|
| **Baked Brick** | Warm, porous, sun-baked clay | Pyramid tiers, building walls |

| **Raw Stone** | Rough-hewn, weathered granite | Foundations, fortifications |
| **Gold Leaf** | Metallic, reflective, precious | Shrine accents, top tier |
| **Reed Mat** | Woven, organic patterns | Tier bonding lines (historical accuracy) |
| **Desert Sand** | Fine, shifting, warm | Ground, surrounding environment |

**Circuit Textures (Night Mode):**

| Texture | Description | Application |
|---------|-------------|-------------|
| **PCB Green** | Dark green fiberglass with traces | Board base, pyramid skin |
| **Copper Trace** | Metallic lines with solder mask | Trace pathways, connections |
| **Silicon Wafer** | Grid-patterned, reflective dark blue | CPU areas, shrine surfaces |
| **Solder Joint** | Silvery metallic blobs | Component connections, nodes |
| **LED Surface** | Glowing, diffused light points | Status indicators, agent glows |
| **Fiber Optic** | Hair-thin light lines | High-speed trace segments |

### 7.2 The Day/Night Transition

The signature visual effect of MEOK is the **seamless transition** between ancient temple and circuit board.

**Transition Trigger:**
- Manual: Player toggles D/N button
- Automatic: In-game time (every 10 minutes)
- Event-triggered: Entering BFT Council forces Night mode

**Transition Animation (3 seconds):**

```
Phase 1 (0-0.5s): Fade to 50% opacity, desaturate
Phase 2 (0.5-1.5s): Texture morph — stone → PCB surface
Phase 3 (1-2s): Color shift — warm palette → neon palette  
Phase 4 (1.5-2.5s): Neon traces FADE IN with flicker
Phase 5 (2-3s): Particle effects activate, glow blooms
```

**Visual Metaphor:** The transition is like **sunset turning to neon dusk** — the pyramid doesn't change shape, only how we SEE it. Stone pores become circuit vias. Weathering lines become trace pathways. The shrine's blue glaze becomes an LED display.

### 7.3 Typography

**Primary Font (Ancient/Hieroglyphic):**
- Family: Cuneiform-inspired display font + modern sans-serif
- Titles: Bold, geometric, monumental proportions
- Body: Clean, readable, neutral

**Secondary Font (Circuit/Digital):**
- Family: Monospace + OCR-inspired
- Data readouts: Monospace, fixed-width
- HUD elements: Small caps, technical

**Hybrid Approach:**
- Headings: Ancient font with circuit-board texture overlay
- Numbers: Always digital/monospace (clarity for data)
- Labels: Context-sensitive (ancient in Day, digital in Night)

## 9. GAME MECHANICS & INTERACTIONS

### 9.1 Camera System

**5 Zoom Levels:**

| Level | Name | View | Detail | Mode |
|-------|------|------|--------|------|
| 1 | **Street View** | Inside a town, walking | Individual agents, buildings | Primarily Day |
| 2 | **Town View** | Single component + connections | Town stats, nearby agents | Mixed |
| 3 | **Regional View** | Multiple towns + trace network | Regional heat map | Mixed |
| 4 | **World View** | Full circuit board visible | All traces, pyramid centered | Primarily Night |
| 5 | **Cosmos View** | Pyramid as single node in network | Galactic network, other pyramids | Night only |

**Camera Controls:**
- Scroll/Pinch: Zoom between levels
- Drag/Pan: Move around current level
- Double-click: Focus on element (town, trace, agent)
- Long-press: Context menu

### 9.2 Click Interactions

**Click Pyramid:**
- Zoom to appropriate tier based on current zoom level
- Show tier information panel
- Triple-click: Enter BFT Council Chamber (Tier 7)

**Click Trace:**
- Highlight entire trace path
- Show traffic data: agent count, throughput, compliance
- Follow mode: Camera follows a "representative" agent

**Click Town (Component):**
- Zoom to Town View
- Show component detail split-screen
- Options: Enter town, view agents, propose action

**Click Agent (Signal):**
- Track camera to follow agent
- Show agent stats: role, civilization, compliance history
- Options: Inspect, communicate, sanction (if authorized)

### 9.3 BFT Council Gameplay

**Entering the Chamber:**
- Camera zooms rapidly through all 7 tiers
- Each tier flashes past with increasing glow
- Final transition: Through glass floor into shrine

**Inside the Chamber:**
- 13 seats arranged in circle, each with holographic display
- Center: Large consensus visualization (3D logic gate)
- Proposal appears as "signal" entering from outside
- Voting: Click your seat's vote button → pulse travels to center
- Consensus: Logic gate processes → result burst

**Visual Feedback:**
- YES vote: Green pulse to center
- NO vote: Red pulse to center
- ABSTAIN: Yellow pulse
- Consensus reached: Golden ring expands from center
- Rejected: Ring collapses, red flicker

### 9.4 Pheromone Mechanics (Visualized)

**Deposit:**
- Agent releases colored "smoke" (Day) / "voltage pulse" (Night)
- Effect diffuses along trace, fading over time
- Other agents see glow and can follow

**Evaporation:**
- Pheromone trails fade gradually (visible as dimming glow)
- Old paths become ghostly faint traces
- Fresh deposits are bright and attractive

**Following:**
- Agents "sniff" by checking pheromone gradient
- Visual: Agent tilts toward strongest signal like a compass needle
- Successful follow: Agent accelerates, trail brightens

### 9.5 Compliance Enforcement

**Detection:**
- Violation appears as RED SPARK on affected trace
- Component LED turns red
- Notification pulse travels to pyramid

**Escalation:**
- Level 1: Warning (yellow border on component)
- Level 2: Fine (red pulse, agent speed reduced)
- Level 3: Sanction (trace segment darkens, agents blocked)
- Level 4: Expulsion (component ejected from board, fades out)

**Resolution:**
- Compliant behavior gradually restores green glow
- "Good behavior" bonus: Extra bright glow, efficiency boost
- Public compliance: Other agents see the resolution, learn

## 10. ANIMATION & TRANSITION SYSTEM

### 10.1 Core Animation Principles

1. **Everything pulses** — circuit boards are alive with electricity
2. **Stone is heavy, light is fast** — ancient elements move slowly, digital elements instantly
3. **Glow = importance** — brightest elements are most significant
4. **Color = identity** — civilization colors are consistent across all contexts

### 10.2 Key Animations

**Agent Spawn:**
```
1. Component LED flashes
2. Bright point appears at component center
3. Particle "jumps" onto trace
4. Trail appears behind (fades over 2 seconds)
5. Agent settles into travel speed
Duration: 0.8 seconds
```

**Agent Travel:**
```
Continuous: Glow pulse synced to speed
Junction: Brief brightness spike when changing traces
Arrival: Deceleration, bright flash, absorption into component
```

**Vote Cast:**
```
1. Player clicks vote button
2. Pulse shoots from player position toward center
3. Pulse leaves colored trail
4. Pulses from other players converge
5. Logic gate at center activates (flash)
6. Result pulse shoots upward to consensus display
7. Display updates with new color/state
Duration: 2-3 seconds (varies by network)
```

**Day/Night Transition (Full):**
```
Phase 1: Sky gradient shifts (warm → cool)
Phase 2: Ambient light dims, shadows lengthen
Phase 3: First neon traces flicker on (like streetlights)
Phase 4: Full circuit board reveal with "power-on" sweep
Phase 5: Particle system switches (sand → data rain)
Total: 8 seconds, smooth easing
```

**Violation Alert:**
```
1. Red spark at violation point
2. Spark travels ALONG trace toward pyramid
3. Trace pulses red in wave pattern
4. Pyramid tier LED flashes
5. Global status bar updates
6. Alert sound + visual notification
Duration: 3-5 seconds
```

**Consensus Celebration:**
```
1. Final vote pulse reaches center
2. Brief pause (anticipation)
3. Golden ring EXPLODES outward from center
4. Ring travels down ALL traces simultaneously
5. Every component flashes gold momentarily
6. Pyramid summit glows intense white-gold
7. Particles: confetti (Day) / spark shower (Night)
Duration: 4 seconds
```

### 10.3 Transition Easing

| Animation | Easing | Reason |
|-----------|--------|--------|
| Camera zoom | `easeInOutCubic` | Smooth, cinematic |
| Agent movement | `linear` (with slight `easeInOut` at ends) | Natural motion |
| UI appear | `easeOutBack` | Playful, bouncy |
| UI disappear | `easeInQuad` | Quick, efficient |
| Color shift | `easeInOutSine` | Smooth transition |
| Pulse effects | `easeOutExpo` | Sharp attack, soft decay |
| Alert flashes | `steps(4)` | Urgent, staccato |

## 11. IMPLEMENTATION ROADMAP

### 11.1 Option Analysis for Nick's Caravan Setup

**Context: Nick's setup = portable, possibly limited connectivity, needs to work on modest hardware.**

| Option | Engine | Pros | Cons | Best For |
|--------|--------|------|------|----------|
| **A** | Unreal Engine 5 | Cinematic quality, Nanite geometry, Lumen lighting | Requires powerful GPU (RTX 3060+), 20GB+ install | AAA production, high-end PCs |

- Better performance for 3D walking around

**Minimum Viable: Three.js Only**

- Single codebase, instant deployment

## 12. TECHNICAL APPENDIX

### 12.1 Shader Reference

**Trace Glow Shader (Fragment):**
```glsl
// Core trace rendering with neon glow
uniform vec3 traceColor;
uniform float intensity;
uniform float time;

void main() {
  // Base trace
  float core = smoothstep(0.5, 0.0, distanceFromCenter);
  
  // Outer glow
  float glow = exp(-distanceFromCenter * 4.0) * intensity;
  
  // Pulse animation
  float pulse = sin(time * 3.0) * 0.3 + 0.7;
  
  vec3 color = traceColor * core + traceColor * glow * pulse;
  gl_FragColor = vec4(color, glow + core);
}
```

**Stone-to-Circuit Morph (Vertex + Fragment):**
```glsl
// Blends between stone texture and circuit board texture
uniform sampler2D stoneTex;
uniform sampler2D circuitTex;
uniform float morphFactor; // 0.0 = stone, 1.0 = circuit
uniform float time;

void main() {
  vec4 stone = texture2D(stoneTex, uv);
  vec4 circuit = texture2D(circuitTex, uv);
  
  // Circuit "reveals" along UV coordinates with time
  float reveal = step(morphFactor, uv.x + sin(uv.y * 10.0) * 0.1);
  
  vec4 final = mix(stone, circuit, reveal);
  gl_FragColor = final;
}
```
