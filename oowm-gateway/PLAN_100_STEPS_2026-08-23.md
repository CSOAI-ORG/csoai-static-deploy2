# OOWM → OpenRouter-grade Router + LMArena-grade Arena — 100-Step Plan (2026-08-23)

**Goal:** turn the estate's OOWM router into an **OpenRouter-grade routing layer** (route to the best provider/model per task with cost-quality-latency tradeoffs + auto-fallback) and an **LMArena-grade arena** (Bradley-Terry Elo ranking of our fleet), wire it as a product on Council OS, all working from the runpod with Oracle backup, EAT-verified, in the monorepo. **Learn from OpenRouter + LMArena, apply to ours.**

Grounded in: our `task_router` (knowledge→phi4:14b, governance→mistral:7b, safety→council-oowm), 7-model measured roster, `oowm-gateway.codes`, and OpenRouter's [model routing](https://openrouter.ai/blog/insights/model-routing/) / [auto-router](https://openrouter.ai/blog/announcements/introducing-the-new-auto-router/) / [provider failover](https://openrouter.ai/docs/guides/routing/provider-selection) and LMArena's [Elo ranking](https://aiwiki.ai/wiki/llm_rankings).

## Phase 0 — Learn (OpenRouter + LMArena methodology mapped to ours)
1. Read OpenRouter model-routing doc → note it routes by **provider preference + fallback + cost/latency/quality**.
2. Map OpenRouter's `order` field → our router's specialist-priority ordering.
3. Read LMArena Elo (Bradley-Terry) → map to our GSPC/measured-roster scoring.
4. Note LMArena "wisdom of the market" → our live arena (games/axis) is the same signal.
5. Write a side-by-side: OpenRouter field → our field (model/provider → model+size, fallback → WORKHORSE, provider-order → specialist-priority).
6. Identify the 3 gaps: (a) no cost/latency metadata, (b) no live Elo ranking, (c) no per-request fallback chain.

## Phase 1 — Routing metadata (cost/latency/quality)
7. Build `model_registry.json` — every fleet model + size + t/s + VRAM + measured score.
8. Add **token cost** for API models (OpenRouter/DeepSeek) via pricing records.
9. Add **latency** per model from the measured-roster (already has latency_ms).
10. Add **quality** = our GSPC/measured score (0.60–1.00).
11. Add **provider** field (runpod-a100 / oracle / openrouter / deepseek-official).
12. Add **reliability** flag (known to generate — phi4/mistral yes, qwen3:8b no).
13. Emit a `route_policy` table from registry (task → best model by weighted score).

## Phase 2 — Scoring: multi-objective route selection (like OpenRouter auto-router)
14. Define a cost function: `score = w1*quality − w2*cost − w3*latency`.
15. Tune weights (quality-first for governance/safety; cost-first for bulk knowledge).
16. Implement `choose_route(task, query)` = argmax over the fleet.
17. Per-task weights: safety→quality(0.9)/latency(0.1); knowledge→cost(0.4)/quality(0.6).
18. Add **budget cap** (skip models over a token budget for a task).
19. Add **latency budget** (skip cold-start > X on interactive, allow on batch).
20. Emit the decision + rationale (transparent routing, like OpenRouter's explain).
21. Test the cost function on the 7-model roster → verify it picks phi4 for knowledge.

## Phase 3 — Fallback chain (OpenRouter provider failover)
22. Implement ordered fallback: primary → WORKHORSE → openrouter → deepseek-official.
23. On primary error/timeout → next in chain (we have WORKHORSE; add OpenRouter+DeepSeek).
24. Add OpenRouter as an external fallback provider (route to top-tier if local fails).
25. Add DeepSeek-official as a second external fallback (the estate already has that key).
26. Add per-model health flag (auto-mark a model down after N failures).
27. Circuit-breaker: if a model fails 3× in 5 min, skip it for 5 min.
28. Retry-once semantics for non-idempotent (but our inference is idempotent → retry safe).
29. Log every fallback (which model, why, fallback used).
