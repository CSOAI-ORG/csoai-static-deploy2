## How it stays living

1. Mining (web or estate) lands raw notes in `_mining/`.
2. `python3 build_catalog.py` re-folds everything into `catalog.json` + the per-kind cards.
3. The MCP server reads `catalog.json` on every call — never stale, no rebuild needed.
4. Anything new in the estate that names a framework/charter/regulation/article is
   expected to be drummed (added to the seed or `_mining/`) — that is the ingestion floor
   of the self-propagating loop (§3 of the master doc).

## Honesty rules (binding)

- `UNMEASURED` stays `UNMEASURED` — a gap in the drum is reported as a gap.
- Doctrine-clean naming: no banned strings on public surfaces (see the master doc's naming discipline).
- Every item carries its source URL / estate path; nothing is asserted without a source.
- **Internal-item hygiene:** items whose name/description carries an internal codename are
  flagged `internal: true`, their descriptions are scrubbed, and the MCP server **filters them
  from all public responses** by default (`include_internal=true` re-exposes them). `catalog.json`
  is the internal master index — never re-export it publicly without running the filter.
