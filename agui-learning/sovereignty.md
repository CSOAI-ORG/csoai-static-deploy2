## What CSOAI Should Adopt — 5 Concrete Improvements for the AG UI Sovereignty Chat Window

### 1. Portability predicates (machine-checkable, GDPR Art 20 + Data Act shaped)
Surface sovereignty as a live set of booleans the window evaluates per system, each returning ✓ / ✗ / **UNMEASURED**:
- `format.machine_readable` — export is structured/commonly-used/machine-readable (JSON/CSV/ActivityPub/GGUF), not PDF-only.
- `hindrance.free` — no egress charge, no rate-limit wall, no "contact sales to export" gate.
- `direct_transfer.feasible` — a controller→controller (or tool→tool) transfer endpoint exists.
- `legal_basis.in_scope` — processing rests on consent/contract (Art 20 scope), not public-interest.
Each predicate links to the fetched evidence and shows the exact artifact path/bytes when it passes. This is the direct translation of competitor #1 (and #7's charge timetable) into a measurement instrument.

### 2. Exit checks (one-click "leave" simulation, Mastodon + AI Act shaped)
Add an **Exit Check** that, in a single click, verifies the user can leave cleanly and reports a verdict per verb (mirroring AI Act recall/withdrawal semantics):
- `export` — full archive downloadable (Takeout-style, per-scope).
- `redirect` / `move` — identity can be relocated without losing the graph (Mastodon `Move`-style).
- `disable` — the system can be taken out of service / account disabled.
- `delete` — irreversible erasure available and stated as separate from export (Takeout's "download ≠ delete").
Show a cooldown/irreversibility warning before any destructive verb, and make the whole check replayable (deterministic, signed).

### 3. No-lock-in verification (Solid + Ollama + Data Act shaped)
Add a **No-Lock-In** check that tests three concrete properties:
- **Open format**: exported artifacts use an open, re-importable format (GGUF / ActivityPub JSON / Solid-Pod-compatible HTTP resources), not a proprietary dump.
- **Identity/store decoupling**: identity (WebID-style) is separate from storage, so leaving is a move, not a rewrite.
- **Zero egress + functional equivalence**: no switching charge (Data Act Art 29 after 12 Jan 2027) and a stated exit that preserves function (Art 25 functional equivalence).
Any item that cannot be proven is rendered **UNMEASURED** — never defaulted to pass.

### 4. Signed, portable provenance + policy on the export (C2PA + DSP shaped)
When the Sovereignty window produces an export or a verdict, wrap it in a **tamper-evident manifest** (C2PA-style: claim + signed assertions + ingredient chain) **and** attach the usage policy (DSP-style) that travels with the artifact. Reuse CSOAI's existing ed25519 signed h3k-card pipeline: the portability result should itself be portable and independently verifiable — a user leaving CSOAI can take their signed measurement history with them and verify it elsewhere. Never certify; only sign what was actually measured.

### 5. Scope honesty + right-to-explanation in plain language (EDPB + AI Act Art 86 shaped)
Add a plain-language panel that (a) states the **EDPB scope split** — "data *provided by you* (exports) vs. data *derived about you* (does not)" — and (b) explains, in one paragraph, *what leaving does* (which verbs fire, what is preserved, what is erased). Honor AI Act Art 86's "clear and meaningful explanation of the role + main elements." Anything outside a verified predicate is labeled UNMEASURED. This protects CSOAI's **neutrality** (the asset): we measure and report, we do not silently claim compliance we cannot prove.
