> +1 to this pattern — and we'd be glad to align. We've been building in the same direction with a small opt-in hooks package (`inspect-receipts`, Apache-2.0) in the `wandb_weave.py` / `mlflow_tracking.py` style — `on_task_end` / `on_run_end` emit RFC 8785 canonical-JSON, SHA-256-content-addressed, Ed25519-signed receipts over the produced log hashes, with an offline `verify` CLI and optional `did:web` key binding. Same register as proposed here: non-repudiable evidence of what was claimed and when — not proof the eval is honest or uncontaminated.
>
> On proofbundle specifically (which we've read, v4.0.0): its crypto layer (Ed25519 + JCS + Rekor offline verification + prereg commitments + public-beacon per-sample audits) is genuinely solid. What we'd add on top is the governance layer it doesn't carry: `did:web` identity binding, correction/supersession chains, a statistics package (Wilson CIs / MDE), and an appeals path. We'd rather merge efforts than run a format war — happy to propose a common receipt envelope covering both backends, contribute ours as a second example hook, or keep it as an external package the docs can point to. Whatever the maintainers prefer.
